## 这是什么

知行朋友圈是一套 **App + Web + 云端** 的个人人脉管理方案，面向房产经纪人、销售、自由职业者等需要长期精细化运营人脉的人群。

它基于 **「ABC 客户分层 + 弱关系维护」** 方法论构建：

- **分层运营** —— S/A/B/C/D/V 六级分层，不同关系强度用不同精力维护
- **标签体系** —— 身份标签（是谁）+ 属性标签（什么状态）+ 业务字段（具体需求）
- **模板驱动** —— 6 个行业预设模板（房产 / 保险 / 电商 / 教育 / 医疗 / 通用），一键应用整套分层与标签体系
- **跟进记录** —— 每次接触留痕，下次跟进不再遗忘
- **云端同步** —— 手机端与 Web 端数据实时互通
- **数据治理** —— 重复检测合并、通讯记录去重、时光机回滚

> 本项目是 **服务端 + Web 前端**。Android 手机端见 [zhixing-circle-app](https://github.com/x2it/zhixing-circle-app)。

## 功能亮点

### 联系人管理

- 六级分层（S/A/B/C/D/V）+ 拖拽调整，批量改层
- 身份标签 / 属性标签 / 自定义标签，多对多关联
- 备注名格式规范（如 `A·张哥（要买悦中心）`），分层前缀一眼识别关系强度
- 业务字段随模板变化 —— 房产经纪看「购房预算 / 意向区域」，保险顾问看「险种意向 / 年缴预算」
- 分页排序筛选，支持按分层、标签、待跟进、无手机号等维度过滤

### 模板体系

- **6 个行业预设模板**，覆盖房产 / 保险 / 电商 / 教育 / 医疗 / 通用场景
- **另存为新方案** —— 基于预设派生自定义模板，改崩了能一键重置回初始状态
- **恢复出厂** —— 清空全部自定义方案，回到干净的 S/A/B/C/D/V 出厂配置
- **apply 报告** —— 应用模板后返回标签新增/跳过统计，透明可追溯

### 云端同步（核心能力）

- **分片上传通道** —— 突破网关体积限制，大批量数据分片上传
- **幂等保证** —— 短信按 `手机号 + 时间 + 内容哈希` 去重，通话按 `手机号 + 时间 + 方向 + 时长`，失败重试绝对安全
- **宽容归一化** —— 时间支持 6 种格式（字符串 / ISO / 时间戳），方向支持中英文混写，时长支持 `120s` / `2:00`
- **设备握手** —— App 启动上报环境能力，云端下发同步限制与规范，两边不再"对不上"
- **同步健康面板** —— 每台设备的环境、每次同步的成败、失败原因，Web 端一屏可见

### 数据治理

| 能力 | 说明 |
|---|---|
| **重复检测合并** | 按归一化手机号判重；同名仅提示（同名未必同人），人工确认后才合并，写日志可追溯 |
| **碎片批次合并** | App 分批同步产生的几十个碎片批次一键合并，导出可整批选中 |
| **通讯去重** | 短信/通话完全重复记录清理（每组保留最早一条），先预览后执行 |
| **名称前缀清洗** | 识别 `yj陈铁兵` / `b北京李哥` 这类手工前缀，可批量去前缀或转标签 |
| **数据时光机** | 按批次回滚导入，支持多选批量回滚，保守判定避免误删 |

## 技术架构

```
┌─────────────────────────────────────────────────────┐
│                    客户端层                          │
│   Web (React 19 + Vite + Tailwind + shadcn/ui)      │
│   Android App (Kotlin + Compose) → 独立仓库          │
└─────────────────────────────────────────────────────┘
                          │
                    REST API (共享类型契约)
                          │
┌─────────────────────────────────────────────────────┐
│                    服务端层                          │
│   NestJS 10 + Drizzle ORM + PostgreSQL              │
│   ├── 认证鉴权（会话 + API Key 双通道）              │
│   ├── 业务模块（联系人/标签/跟进/模板/沟通记录）      │
│   ├── 同步通道（分片上传 + 幂等写入 + 设备握手）      │
│   └── 数据治理（合并/去重/清洗/回滚）                │
└─────────────────────────────────────────────────────┘
```

### 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19 · TypeScript · Vite · Tailwind CSS · shadcn/ui · TanStack Query |
| 后端 | NestJS 10 · TypeScript · Drizzle ORM · PostgreSQL |
| 全栈底座 | 飞书 aPaaS Fullstack（`@lark-apaas/fullstack-nestjs-core`） |
| 类型契约 | `shared/api.interface.ts` —— 前后端共享同一份类型定义 |

### 工程亮点

**1. 共享类型契约（`shared/`）**

前后端共用一份 TypeScript 接口定义，任何字段变更在编译期就能发现不一致，杜绝"接口对接靠口头约定"。

**2. 幂等同步设计**

```
短信去重键：phone + message_date + md5(body)
通话去重键：phone + call_date + direction + duration
联系人：    external_id（App 端通讯录 raw_contact_id）
```

同一个同步请求发 100 次，结果与发 1 次完全相同。

**3. 同步可观测性**

每条同步事件（start / commit）落 `operation_logs`，记录条数、体积、耗时、成功/跳过/失败数、失败原因 TOP3。设备握手注册表独立存储，Web 端可视化呈现。

**4. 破坏性操作全链路保护**

所有删除/合并类操作遵循统一模式：**先预览 → 人工确认 → 服务端执行 → 写操作日志 → 支持回滚**。

## 快速开始

### 环境要求

- Node.js 20+
- PostgreSQL 14+
- npm 10+

### 本地运行

```bash
# 1. 克隆
git clone https://github.com/x2it/zhixing-circle.git
cd zhixing-circle

# 2. 安装依赖
npm install

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env，填入你的 PostgreSQL 连接串

# 4. 初始化数据库
#    建库后按 server/database/schema.ts 定义建表
createdb zhixing

# 5. 开发模式启动
npm run dev
```

访问 http://localhost:3000

### 生产构建

```bash
npm run type:check    # 类型检查（前后端）
npm run build:prod    # 生产构建
npm start             # 启动服务
```

### 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `SUDA_DATABASE_URL` | ✅ | PostgreSQL 连接串 |
| `SERVER_HOST` | | 监听地址，默认 `127.0.0.1` |
| `SERVER_PORT` | | 监听端口，默认 `3000` |
| `NODE_ENV` | | `production` / `development` |
| `FORCE_AUTHN_INNERAPI_DOMAIN` | | 平台认证域名，自托管可填占位地址 |

## 数据安全边界

本工具处理的是**用户最敏感的人脉数据**，设计上遵循以下原则：

- **同名 ≠ 同人** —— 联系人合并必须人工勾选确认，系统绝不自动合并
- **破坏性操作可回滚** —— 导入批次支持时光机回滚，恢复导入前状态
- **原始记录优先** —— 去重只删「完全相同的重复记录」，不同时间的正常记录一律保留
- **操作留痕** —— 合并、清理、回滚全部写入操作日志，可追溯
- **数据自主** —— 支持全量导出（JSON / CSV / vCard / Excel），数据永远属于用户

## 与旧版 TMA 的关系

[**TMA（电话营销助理）**](https://github.com/x2it/TMA) 是知行朋友圈的前身 —— 一个纯单机版 Android 电销助手，专注「拨号 → 登记 → 下一位」的外呼作业闭环，数据全部本地存储，**已停止更新并归档**。

知行朋友圈是 TMA 的官方云端继任版本：保留了拨号跟进的核心体验，同时增加了云端同步、通讯录/短信/通话双向备份、标签分层体系和 Web 管理端。

| | TMA（已归档） | 知行朋友圈（当前） |
|---|---|---|
| 定位 | 单机电销作业工具 | 人脉关系运营 + 云端同步 |
| 形态 | Android 原生 App | App + Web + 云端 |
| 数据 | 全部本地 | 云端同步，多端互通 |
| 状态 | 停止更新 | 活跃维护 |

> 老用户如需继续使用纯单机方案可参考 TMA，但新项目和新功能均在知行朋友圈上开发。
