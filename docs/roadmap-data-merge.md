# 知行朋友圈 · 「数据功能并入联系人」融合方案

> 2026-09-29 · 本轮只出方案不实施。目标：呼应「拳头功能（云端同步 + 通讯录管理）要重、短信/通话轻量化、全局系统性高效处理」的产品原则。

## 一、现状问题

导航 8 项：仪表盘 / 联系人 / 沟通记录 / 标签 / 朋友圈 / 数据 / 模板 / API。

| 问题 | 具体表现 |
|---|---|
| 「数据」页成了杂物抽屉 | 数据治理 4 卡（批次合并 / 前缀清洗 / 重复检测 / 通讯去重）+ 时光机 + 导入导出 + 清空 + 质量统计，全堆在一页，滚动 4 屏起步 |
| 发现与操作混在一起 | 「重复联系人」「碎片批次」这些问题藏在数据页里，用户不主动去就永远不知道数据脏了 |
| 沟通记录重流水轻人物 | 短信/通话以原始流水为主，而用户真正的问题是「这个联系人最近聊了什么」 |

## 二、方案总览（三步走）

### 一期 · 发现上浮，操作留位（推荐先做，改动小收益大）

**核心：联系人页做「数据体检」入口，数据页专注做「操作台」。**

1. 联系人页头部新增可折叠「数据体检条」：
   `⚠ 12 位重复联系人 · 36 条重复短信 · 8 个碎片批次 → 一键体检`
   - 数字由现有接口直接算（findDuplicates / comm-dedup/preview / batches 列表），零新增后端
   - 无问题时显示 `✓ 数据很干净`（绿色一条细线，不占视觉）
2. 点击各项直达数据页对应卡片（页面锚点定位 + 卡片自动展开），操作仍在数据页完成
3. 数据页 4 张治理卡按使用频率重排：重复检测（人工确认制）→ 通讯去重 → 批次合并 → 前缀清洗

**为什么这样分**：发现问题和解决问题分离。联系人页是每日主战场（拳头功能），体检条让它「顺便」承担数据健康感知；数据页保持工具属性，不被稀释。

### 二期 · 「数据」更名「数据中心」，内部分三区

- **体检区**：重复联系人 / 重复短信通话 / 碎片批次 / 无号码 / 未分层，自动统计 + 一键修复入口
- **时光机**：回滚中心（已有批量回滚能力，补全按批次多选体验）
- **迁移区**：导入（xlsx/csv/json/vcf）+ 导出 + 清空（危险区视觉降级，默认折叠）

桌面侧栏同步分组（移动端底部 5 项不动）：

```
关系：联系人 / 标签 / 朋友圈
记录：沟通记录
系统：数据中心 / 模板 / API
```

### 三期 · 联系人详情内嵌「时间轴」（真正意义的融合）

联系人详情抽屉新增「时间轴」Tab：该联系人的短信 / 通话 / 跟进记录按时间倒序融合成一条线，每条记录带来源图标。

- 这才是「数据融合到联系人」的最终形态：以人为维度看全部交互历史
- 沟通记录页退居「跨联系人全局检索 + 批量清理」的轻量工具页，符合短信/通话轻量化定位
- 依赖：messages/calls 表已有 contact_id 关联（联系人合并时已做迁移），技术上无阻塞

## 三、取舍原则（回应「原始记录 vs 聚合」）

| 场景 | 默认呈现 | 原始记录 |
|---|---|---|
| 联系人时间轴（三期） | 按人聚合，每联系人一屏 | 点击单条展开完整内容 |
| 沟通记录页 | 按联系人聚合视图优先 | 流水模式作为次级 Tab 保留 |
| 去重清理 | 只删完全重复，聚合统计不做破坏性删除 | — |

原则一句话：**聚合是默认视图，原始记录永远可达、永不被删除**。破坏性操作只发生在「完全重复」这一种情况，且必须先预览。

## 四、实施成本评估

| 期 | 前端改动 | 后端改动 | 预估 |
|---|---|---|---|
| 一期 | 联系人页体检条 + 数据页锚点跳转 + 卡片排序 | 无（全部复用现有接口） | 1 次迭代 |
| 二期 | 数据页三分区重排 + 侧栏分组 | 无 | 1 次迭代 |
| 三期 | 详情抽屉时间轴 Tab | 无（复用 messages/calls 按 contactId 查询） | 1~2 次迭代 |

风险提示：
- 二期改导航是用户习惯变更，建议一次到位并保留旧路径重定向（/data → /data-center）
- 三期时间轴单联系人数据量大时需分页/虚拟滚动（先按最近 100 条 + 加载更多即可）

## 五、数据安全边界（贯穿各期）

- 体检条只读，不自动执行任何修复
- 所有清理操作维持现状：先预览 → 人工确认 → 服务端执行 → 写操作日志
- 「同名≠同人」原则不变，联系人合并永远人工勾选确认
